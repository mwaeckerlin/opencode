# Features

Numbered register of every feature; a number is never reused. Every feature is covered by tests listed in [TESTS.md](TESTS.md); the guard `tests/docs-contract.sh` fails when a feature has no test.

- **F1 — OpenCode in the browser.** The sandbox runs OpenCode with its web interface on port 4096, in the working directory `/workspace`, with the full toolset of `mwaeckerlin/sandbox-base`.
- **F2 — Models through LiteLLM.** `OPENCODE_MODELS` names the LiteLLM models OpenCode offers, the first as its default; every model call goes through the gateway.
- **F3 — Two memory banks.** OpenCode reaches the bank shared by all agents and a bank of its own as the MCP servers `hindsight-shared` and `hindsight-own`, through the gateway.
- **F4 — No key in the sandbox.** Neither the environment, nor the configuration, nor any file of the sandbox holds a key; OpenCode sends a placeholder.
- **F5 — The gateway adds the keys.** The gateway replaces the Authorization header with the LiteLLM key on `/v1/…` and the Hindsight key on `/mcp/…`, each read from a Docker secret, and streams the answer back.
- **F6 — One way out.** The sandbox reaches only its gateway; the gateway answers every path except `/v1/…`, `/mcp/…` and `/health` with 404, a path with a dot segment included.
- **F7 — Clear start errors.** A missing or empty key file, an upstream address that is not http or https, an unreachable upstream (502) and an invalid bank id each stop or answer with a message that names the cause.
- **F8 — Headless gateway.** The gateway image contains no shell, no busybox and no perl.
- **F9 — Published for amd64 and arm64.** Every push builds both images natively for both architectures and publishes them on Docker Hub, with the reusable workflow of `mwaeckerlin/scratch`.
- **F10 — Development agent for other agents.** One central OpenCode server serves the web interface and the agents that delegate development to it, such as Hermes and OpenClaw: they send a task through the server API and get the answer back in the response, or hand it over with `opencode run --attach`.
- **F11 — Optional server password.** With `OPENCODE_SERVER_PASSWORD_FILE`, the web interface and every attaching agent need the password; without it the server is open.
- **F12 — Optional keys.** Without a key file, the gateway forwards that route without any Authorization header, for a deployment whose network decides who reaches LiteLLM and Hindsight.
- **F13 — Web interface below a path.** The administrator who publishes OpenCode under a path of a shared address, such as `https://swarm-01/opencode`, sets that path in the sandbox, and the user opens the web interface there: the page, its files, every call to the server, the live updates and the terminal connections all stay below the path, and so do the addresses of the interface's own navigation. The reverse proxy passes the path on as it is and changes no page. The bare path `/opencode` leads to `/opencode/`. Agents inside the stack still reach the server at its root address, such as `http://opencode-sandbox:4096`. Without a path, or with `/`, the web interface lies at the root as before. A path without a leading slash, with a space or with a `..` or `.` segment stops the start with a message that names the setting.
- **F14 — Published address chosen by the operator.** `docker-compose.yml` publishes the web interface of the sandbox on port 4096 of every address of the host, IPv4 and IPv6, as long as `BIND_ADDRESS` is unset or empty, so an installation that never set it stays reachable as before. `BIND_ADDRESS` limits the port to that one address: `127.0.0.1` for the local machine alone, an IPv6 address in brackets such as `[::1]`; `0.0.0.0` publishes on every IPv4 address and on no IPv6 address.
- **F15 — Login link in the web interface.** The user whose subscription model stopped answering finds the way to sign in again in the web interface: where the administrator has named the address of the login page of the LiteLLM subscriptions, every page of the web interface shows the link «Subscription login» at the right end of a narrow bar above the interface, in its colours, light or dark, at the root and below a base path, on a phone and in the view of a session too; the interface fills the rest of the window, so the link covers no tab and no control, and nothing of the interface is cut off. The link opens the login page in a window of its own, and its address stays as the administrator wrote it, also below a base path on the same host. Without the address there is no link. An address that is not http or https stops the start with a message that names the setting.
- **F16 — Alerts in the chat.** The administrator who watches the LiteLLM subscriptions with Grafana or Alertmanager sees their alerts in the web interface: the sandbox keeps one session for alerts, titled «Alerts» unless he names another title, which exists from the start, is found again after every restart, and is created anew after the user deleted it. A webhook with the alert token puts the alert into that session as a message the model does not answer: the title and message of a Grafana alert, one line per alert of an Alertmanager alert (status, name, summary or description, source address), any other JSON as it stands, plain text as it stands, followed by the login link where one is set. The sender holds the token, the sandbox only its digest. A webhook without the token, with another token or with the server password answers 401 and reaches no session; an empty body answers 400, another method than POST or PUT 405, a body above the limit (1MiB unless set otherwise) 413, and an OpenCode that does not take the alert 502 with the cause. The webhook is taken at the root and below a base path. A digest that is not 64 hexadecimal digits, a title of more than one line or of more than 200 characters, and a limit that is no positive number stop the start with a message that names the setting.
- **F17 — Login link in the chat when a subscription model fails.** Where the login address is set, a failed answer of a subscription model, a LiteLLM model whose name starts with `mysubs/` unless the administrator names another start, adds a message to its session with the model, the error LiteLLM reported and the login link; the model does not answer that message. Every failure of such a model adds it, whatever the cause; an answer the user stopped, a failing model outside the subscriptions and a model that answers add none. A retryable failure adds the message once OpenCode has given up retrying.
